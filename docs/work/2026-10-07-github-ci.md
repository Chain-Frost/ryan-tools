## Outcome and scope

Introduced useful GitHub Actions checks for pull requests and pushes to `main`, comparable to the Python CI in
`run-hy8` and `ryan-culverts`. Hosted CI must state what it validates and must not depend on executables or licensed
application environments installed on the maintainer's machine.

This is the completed implementation record. The workflow remains branch-local until PR #96 is merged. Read
[AGENTS.md](../../AGENTS.md), the [development guide](../DEVELOPMENT_GUIDE.md),
[environment guidance](../ENVIRONMENTS.md) and [work tracking](../WORK_TRACKING.md) before implementation.
Implementation is authorized on the existing `fix/issue-95-baseline-test-failures` branch and PR #96. Do not merge the PR as part of this work.

## Current state and constraints

- This branch now contains an enabled Python CI workflow; it is not repository-default policy until PR #96 is merged.
  The existing auto-review workflow is disabled; leave its unrelated behavior alone.
- Normal development uses Python 3.14. Start hosted validation on Windows to match repository path assumptions;
  defer a broader OS matrix until the initial job passes and portability expectations are defined.
- Development dependencies are installed through `requirements.txt`, which selects the editable `dev` extra.
  Rasterio/Fiona dependencies do not establish that `osgeo` bindings or GDAL command-line tools are available.
- `tests/conftest.py` requires fixture data at session start. Missing required fixtures must fail setup rather than
  silently skip tests. Its current recursive-submodule recovery advice also needs correction.
- Existing `gdal`, `gui` and `slow` markers are declared in `pytest.ini`. They do not yet define a reliable hosted
  test boundary. Some modules import `osgeo` during collection without a GDAL marker; deselection alone cannot fix this.
- Vendored Python packages can be tested without launching their external applications. Keep HY-8 executable
  validation distinct from importing and testing the bundled `run_hy8` package.
- Do not initialize, inspect, traverse or validate `unsorted`. Do not use recursive submodule checkout.

## Implemented jobs

| Job | Responsibilities | Environment boundary |
| --- | --- | --- |
| Policy | Changed-Python Ruff lint/format and strict Pyright; documentation and logging checks | Python 3.14; no external applications |
| Hosted tests | Algorithms, processors, workflow contracts, synthetic raster processing, wrapper dry runs and mocked subprocess behavior | Explicit installed dependencies and repository fixtures |
| Package | Verify retained wheel, rebuild without version bump, verify candidate and isolated installed imports/resources | Bundled Python packages; no HY-8/TUFLOW launch |
| GDAL integration | Real `osgeo` operations and any required GDAL tools | Explicitly provisioned compatible GDAL environment; separate from initial core job |

Jobs should be independent so a policy failure does not hide runtime or packaging results. Use read-only repository
permissions, timeouts and cancellation of superseded runs. Review current supported action versions when implementing.
PowerShell steps must propagate every native command failure explicitly; a later successful command must not mask it.

## External-software and warning contracts

- Real 7-Zip archive integration tests are optional local checks. Hosted CI explicitly ignores
  `tests/scripts/test_archive_compress.py`, even if a runner happens to have 7-Zip installed. Local runs retain the
  existing availability-based skip behavior. Keep any separate mocked archive tests eligible for hosted CI.
- JUnit output is a machine-readable XML test report containing pass, failure and skip results. Pytest writes it using
  `--junitxml`; no Java installation is required. Upload it as a CI artifact for diagnosis.
- ASC_to_ASC parity, HY-8 executable comparisons, licensed TUFLOW runs and QGIS/OSGeo4W application smoke checks remain
  explicit local validation unless a separately provisioned environment is established.
- The maintainer's confirmed ASC_to_ASC path is
  `C:\TUFLOW\asc_to_asc.2024-06-AB\asc_to_asc_w64.exe`. Set `ASC_TO_ASC_EXE` for local parity; never assume this path on GitHub.
- Prefer deliberate deselection with a stated reason for tools outside hosted scope. A job that claims to validate a
  required capability must fail when it is missing, rather than turn green through skips. An explicitly configured
  invalid executable path must fail.
- Expected warnings belong in narrow `pytest.warns()` assertions at the operation that emits them. Preserve the
  missing-CRS test cases. Do not silence all GIS warnings. Introduce all-warnings-as-errors only after auditing the
  selected hosted suite; the focused result below does not establish that the whole suite is warning-clean.

## Completion criteria

- Clean hosted setup obtains required fixtures and dependencies without touching excluded submodules.
- Core tests collect and run without local executables or accidental `osgeo` requirements.
- External tests and GDAL coverage have documented, enforced boundaries; every skip has an actionable reason.
- Policy, hosted runtime and package jobs produce independently inspectable results on PRs and `main` pushes.
- Retained and rebuilt artifacts verify; isolated imports and packaged resources pass; version metadata remains unchanged.
- Current-head GitHub results are recorded after an authorized push. Local passes alone do not establish hosted success.

## Progress
