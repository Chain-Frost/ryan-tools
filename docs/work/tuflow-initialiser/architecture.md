# Architecture and current scope

- Modelling strategy: entirely 2D rainfall-on-grid (ROG); initial geometry only.
- Inputs: one or more **ordered** terrain rasters (highest priority first), AOI polygon(s), optional upstream catchment exclusion polygon(s), configurable AOI circle buffer (500 m default), stream accumulation threshold and separate *hydrology analysis resolution*.
- `ryan_library/functions/gdal/terrain_mosaic.py` (former `terrain.py`): GDAL-backed Rasterio WarpedVRT compositing. Valid first-priority elevations win, lower-priority rasters fill voids. Output analysis DEM and per-pixel source-index/provenance raster; reject unsafe raster sizes. No copying or editing original terrain.
- `ryan_library/functions/tuflow/tgc_terrain.py`: PyTUFLOW-based active terrain-stack discovery for selected scenarios. The model-specific consumer retains input priority order.
- `model_terrain.py`: TUFLOW terrain commands in reverse priority (low to high, as later commands override earlier). When raster CRS differs from project CRS, GDAL-backed WarpedVRT produces a projected copy at that source's native/derived resolution, rather than downsampling hydraulic LiDAR to the hydrology raster resolution.
- `grass_runner.py`: noninteractive GRASS `r.watershed -s` to generate D8 flow direction/accumulation; optional `r.fill.dir`. Never modify original DEM during hydrological conditioning.
- `ryan_library/functions/hydrology/d8.py` (former `d8.py`): all raster cells whose downstream direction reaches **any** AOI cell, including AOIs across independent drainage systems; no stream-area threshold truncates the full catchment.
- `geometry.py`: union of full contributing area and Euclidean circular buffer around AOI. Optional exclusion polygons are clipped to contributing terrain, then subtracted from this union. Exclusions must NOT overlap AOI or its required buffer. Original total contributing area remains unaltered for audit. **Detailed excluded-catchment analysis is opt-in** (`--analyse-exclusions`, default false): stream/path calculations and later subcatchment attributes omit excluded cells by default. The global GRASS flow-direction/accumulation processing and AOI catchment delineation still run across the terrain to establish connectivity. Output the detailed analysis extent separately for QA.
- `gis_writer.py`: same geometry footprint for `2d_code` and `2d_rf`, cardinal rectangular `2d_loc` (SW-SE-NE-NW), same canonical attribute schemas as generated by the selected TUFLOW executable.
- `ryan_library/functions/hydrology/profiles.py` (former `profiles.py`): stream networks from contributing-area threshold and separate synthetic headwater extensions toward divides. Equal-area slope of the longitudinal profile uses `S_ea = 2/L² ∫_0^L (z(x)-z_out) dx`, x increasing upstream. The main channel threshold does not alter contributing-catchment delineation.
- `workflow.py`: validates, stages and publishes new TUFLOW projects. Catchment products are opt-in with `--catchments`; the TUFLOW output remains independent of them.
- `catchment_workflow.py`: accepts line or polygon interest features and publishes a catchment-only GeoPackage without creating a TUFLOW directory.
- `cli.py`: installed `ryan-tools` entry points `init`, `build` and `catchments`. QGIS/PyQGIS not required at runtime; optional user-supplied utility source directory.

## Key safeguards

- The default AOI buffer is a **simple circular area**. It cannot guarantee lack of downstream BC influence.
- Upstream exclusions mean incoming flow is absent from the ROG model and **must** be addressed by an engineer separately. No `2d_bc` or unverified hydrograph is generated.
- Vertical datums and systematic LiDAR/SRTM offsets cannot be reliably inferred from horizontal CRS metadata; input elevations require review, particularly along data-source seams.
- Very fine terrain across vast regional extents may exceed practical processing capacity. Hydrology resolution is independently configurable; hydraulic cell size is not chosen here.

## Excluded

No `2d_bc` (future outlet-only), `2d_po`, `2d_mat`, `2d_sa`, ARR processing, model extent optimisation, model cell-size selection, automated maps/reports, or `.trfc`.
